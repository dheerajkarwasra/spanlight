Spanlight stores the prompts and completions your application sends, so you decide what it keeps and for how long. Each project has settings for this: whether to capture prompts and completions, whether to redact email addresses and phone numbers, and how many days to keep traces. This page also covers the secret redaction that always runs, and what deleting a project removes.

## Redaction always runs

Before a span is stored, Spanlight replaces secrets in its input, output, attributes, status message, name and trace name with `[REDACTED]`. It also checks the names of keys in JSON objects. You cannot turn this off. It replaces:

- Spanlight credentials of every kind (API keys, personal access tokens and gateway keys).
- Anthropic keys and OpenAI-style keys, including `sk-proj-` and `sk-svcacct-` keys.
- `Bearer` tokens.
- AWS access key ids, and AWS secret access keys that are labelled as such.
- Card numbers: runs of 13 to 19 digits that pass the Luhn check, when written in groups of four or more digits or unbroken.

Redaction runs before the 1 MB truncation, so a secret cut in half by the limit cannot survive in part.

Redaction is a safety net, not a guarantee. A secret in a shape none of these patterns match is stored as sent, and a card typed in groups of one to three digits is not detected. Identifiers (`user_id`, `session_id`, tags, environment and release) are stored as you send them, so do not put an email address or a secret there. If a payload must never be stored, turn off payload capture instead. [How ingestion works](/docs/concepts/ingestion/#what-is-redacted) has the full pipeline.

## Turn off prompt and completion capture

By default a project stores the input and output of every span. To keep metadata only:

1. Open **Settings, Project**.
2. In the **Data** card, turn off **Capture prompts & completions**.
3. Save.

From then on, spans are stored without their input and output. Tokens, cost, latency, the model and the rest of the span are still stored, and so are the Doctor's request hashes, which are worked out before the payload is dropped.

- The change applies to spans ingested after you save. Traces already stored keep their prompts and completions.
- It covers every way of sending data, including spans the gateway records.
- It does not cover the gateway cache. A gateway key with a cache TTL stores the provider's response body for up to that TTL (at most 24 hours) even with capture off, because a cache hit needs it; see [Gateway cache](/docs/gateway/cache/#privacy).
- To remove what is already stored, shorten the retention period or delete the project.

Only the admin and owner roles can change it. For anyone else the switch is disabled.

## Redact email addresses and phone numbers

A project can also redact email addresses and phone numbers, on top of the secret redaction that always runs. It is off by default, because code-heavy prompts often hold strings that look like an address. The settings screen does not have a switch for it yet, so set it through the API, with the admin or owner role and a [personal access token](/docs/guides/access/) with the write scope:

```bash
curl -sS -X PATCH "$SPANLIGHT_HOST/api/v1/projects/$PROJECT" \
  -H "Authorization: Bearer $SPANLIGHT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"redact_contact_info": true}'
```

The response shows `"redact_contact_info": true`. Send `false` to turn it off again.

While it is on, Spanlight replaces these with `[REDACTED]` in the span name, input, output, attributes and status message, including the names of keys in JSON objects:

- **Email addresses**: a name, `@`, and a domain with at least one dot that ends in letters, such as `jane@example.com`.
- **Phone numbers in international form**: a `+`, then 10 to 15 digits, which may be split by spaces, dashes, dots or brackets, such as `+44 20 7946 0958` or `+1 (415) 555-2671`.

What it does not catch, or catches when you may not expect it:

- Phone numbers written without a leading `+`, such as `(415) 555-2671` or `020 7946 0958`, are not detected.
- Strings that only look like an address are kept: `react@18.3.1` and `user@localhost` are stored as sent.
- An SSH remote such as `git@github.com:org/repo.git` has the shape of an address and is redacted.
- A `+` followed by a long number, such as `+1234567890` in a diff, is redacted.
- The trace name, trace metadata and identifiers (`user_id`, `session_id`, tags) are not covered; do not put contact details there.

The setting applies to spans ingested after you turn it on. Spans already stored keep what they hold; shorten the retention period or delete the project to remove them. It covers every way of sending data, including spans the gateway records, but not the [gateway cache](/docs/gateway/cache/#privacy), which keeps the provider's exact response. A redacted prompt cannot be [replayed](/docs/playground/), and evaluators and dataset imports see the redacted text.

Like secret redaction, this is a safety net and not a guarantee. Names, street addresses, national ids and numbers in other formats are not detected. If a payload must never be stored, turn off payload capture instead.

## Set the retention period

A project keeps traces for 30 days by default. You can set any whole number of days from 1 to 90.

1. Open **Settings, Project**.
2. In the **Data** card, enter a number in **Retention period (days)**.
3. Save.

A worker job runs every hour and deletes, in batches, the traces that started before the cutoff. Their spans go with them. Shortening the period deletes older traces within the next hour. A value outside 1 to 90 is refused.

The same job removes data that is derived from those traces or quotes them, on the same cutoff:

- hourly rollups behind the long-window charts;
- resolved insights, by the time they were resolved, and per-user daily statistics;
- scores, review-queue items and finished online evaluator runs. Online runs from the current month stay, because the evaluator's monthly budget counts them.

Spanlight keeps traces for at most 90 days. For record-keeping that must last longer, such as a regulatory duty to keep logs, schedule JSONL [exports](/docs/guides/exports/) to your own storage, for example a daily job that calls the exports API, and copy each file elsewhere within seven days, before Spanlight deletes it.

Detector runs are kept for seven days whatever the setting. Datasets, experiments and their items are curated by people and are kept, so delete any that hold text you copied from traces. The [Limits reference](/docs/reference/limits/#retention) lists the retention limits.

## Delete a project

To remove a project and everything in it:

1. Open **Settings, Project**.
2. In the **Danger zone**, select **Delete project**.
3. Type the project's slug to confirm.

This deletes the project, its API keys and all of its traces, and it cannot be undone. Admins and owners can do it. The organization's audit log keeps a `project.delete` event with the project's name and slug. The demo organization's project cannot be deleted.

The files of the project's [exports](/docs/guides/exports/) sit in your object storage, not in the database. Deleting the project queues a background job that deletes everything under the project's export prefix. If object storage is not configured, the job skips and there is nothing to delete.

Deleting an organization deletes all of its projects the same way, together with its members and its audit log. Only an owner can do it.

## Exports

Exporting traces writes a CSV or JSONL file to your own object storage. The file holds the prompts and completions your project captured, so treat it like the traces themselves. Members, admins and owners can export; viewers cannot. Exports are made in **Settings, Project, Exports**.

Spanlight deletes an export file seven days after it was made, and when the project is deleted. See [Exports](/docs/guides/exports/).

## Check it worked

- **Capture off.** When it is the only setting you changed, the toast after you save reads "Prompts and completions will no longer be captured." Send a new trace. Open it in **Traces**: the span's Input and Output show "No input captured" and "No output captured", while tokens, cost and latency are still there. Traces from before the change keep their text.
- **Retention.** When it is the only setting you changed, saving a new period shows a toast such as "Traces are now kept for 14 days." Traces older than the period are removed within the next hour.
- **Redaction.** Send a span whose input contains `Authorization: Bearer abcdefgh12345678`. The stored input reads `Authorization: [REDACTED]`.
- **Contact redaction.** With `redact_contact_info` on, send a span whose input contains `mail jane@example.com`. The stored input reads `mail [REDACTED]`.

## Troubleshooting

- **The switch and the retention field are disabled.** Only admins and owners can change them; members and viewers see them read-only.
- **"Keep traces for at least 1 day." or "Traces can be kept for at most 90 days."** The retention period must be a whole number of days from 1 to 90 ("Enter a whole number of days." otherwise).
- **Old traces still show prompts after you turned capture off.** The change applies to spans ingested after you save. Shorten the retention period or delete the project to remove what is stored; see [Turn off prompt and completion capture](#turn-off-prompt-and-completion-capture).
- **A secret appears in a stored prompt.** Redaction matches known shapes only. Turn off payload capture if a payload must never be stored; see [Redaction always runs](#redaction-always-runs).
- **Traces are still there after the retention period.** The cleanup job runs hourly on the worker. Check that the worker is running; see [Troubleshooting](/docs/troubleshooting/#the-worker-is-not-running).
- **Deleting a project: the button stays disabled.** Type the project's slug exactly. The demo organization's project cannot be deleted.
