This page lists, for each exporter library and pinned version, which Spanlight fields a span sent through [OTLP ingestion](/docs/otlp/) fills. Supported means a green fixture: each table below comes from a fixture that holds the exact bytes the library exported for each scenario and the rows Spanlight is expected to store for them. The contract test posts those bytes on every change and checks every field, so the tables cannot drift from what the code does. The [`otlp-matrix-weekly`](https://github.com/dheerajkarwasra/spanlight/actions/workflows/otlp-matrix-weekly.yml) workflow re-records every library at its latest release each week and reports any breakage.

Each cell says one of four things:

- **captured**: Spanlight stores the field from what the library sends.
- **not sent by the exporter**: the library does not send the field in this scenario, so it stays empty ("—" in the app).
- **not read**: the library sends the field in a form Spanlight does not read, a documented non-goal of the OTLP path (OpenInference sends the time to first token as a span event, and span events are not read).
- **not captured**: the scenario stores no value for the field, for example no finish reason on a request that failed.

For which attribute fills which field, see [OTLP attribute mapping](/docs/reference/otlp-mapping/).
